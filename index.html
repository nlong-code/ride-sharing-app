1. System Context Diagram

The system context diagram illustrates how the ride-sharing application interacts with external users and services. Passengers use the application to request rides, while drivers receive ride requests and provide transportation. The system also communicates with payment services, mapping services, and notification services.

External Entities

  • Passenger: Requests rides, enters pickup and destination information, and makes payments.
  • Driver: Receives ride requests, accepts trips, and updates ride status.
  • Payment Service: Processes passenger payments and returns transaction confirmations.
  • Map Service: Provides location information, directions, and estimated travel times.

2. High-Level Architecture Diagram

The high-level architecture shows the major components of the ride-sharing application and how they communicate. The system uses a mobile application, an application server, a database, and external services to manage ride requests and transactions.

Architecture Components

Component Purpose
Passenger Application Allows passengers to register, request rides, track drivers, and pay.
Driver Application Allows drivers to manage availability, accept rides, and complete trips.
Application Server Processes requests and connects the applications to system services.
User Management Handles user registration, login, and authentication.
Ride Management Matches passengers with drivers and tracks ride information.
Payment Management Handles payment processing and transaction records.
Database Stores passenger, driver, ride, and payment information.

3. Initial Data Flow Diagrams

Context-Level Data Flow Diagram

The context-level DFD provides an overview of the entire ride-sharing system as one process. It shows how passengers and drivers exchange information with the application.

Level 1 Data Flow Diagram

The Level 1 DFD breaks the ride-sharing system into smaller processes. It illustrates how information moves through registration, ride requests, driver matching, payment processing, and ride completion.

Level 1 Process Descriptions

  1. User Registration: Collects and verifies passenger and driver account information.
  2. Request a Ride: Receives the pickup location and destination from the passenger.
  3. Match Driver: Identifies an available driver and sends a ride request.
  4. Process Payment: Calculates the fare and processes the passenger's payment.
  5. Complete Ride: Updates the ride status and stores the completed trip information.

Data Store

D1 - Application Database: Stores user profiles, driver availability, ride requests, trip details, and payment records.
